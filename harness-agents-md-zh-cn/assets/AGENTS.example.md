# 工程默认规则

- 编辑前检查仓库状态和适用指令。只处理用户要求的范围，绝不覆盖无关的用户修改。
- 每次修改和提交都保持单一内聚。遵循仓库实际的分支和验证规则；仅在用户要求
  或确有必要时使用 worktree。
- 执行破坏性操作前解析准确目标，并取得尚未具备的授权。

# 子 Agent 协作

- 只委派相互独立且不冲突的工作流。主 Agent（协调者）负责拆分、文件和模块
  所有权、集成、最终审查与验证。
- 根据真实工作选择 Agent，不要机械设置固定角色。
- 不得让多个 Agent 并发修改同一文件或模块。共享状态应只有一个所有者，否则
  顺序执行重叠工作。
- 执行 Agent 只运行其工作所需的最小针对性检查。协调者审查合并后的 diff，
  并运行聚焦的最终验证。
